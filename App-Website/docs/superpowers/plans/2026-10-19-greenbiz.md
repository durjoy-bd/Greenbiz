# GreenBiz Implementation Plan

> For agentic workers: use superpowers:subagent-driven-development for independent implementation, followed by integration review.

**Goal:** Deliver a working GreenBiz Android app and full source matching the supplied green references.

**Architecture:** One React UI serves mobile and responsive web portals. A common domain layer drives a persistent device workspace and an authenticated Fastify/SQLite server.

**Tech Stack:** TypeScript, React, Vite, Capacitor 6, Fastify 5, Node 24 SQLite, Zod, Vitest.

**Spec:** docs/design.md

## Global Constraints

- App name is GreenBiz throughout runtime copy and Android metadata.
- Preserve reference colors #F3F6F2, #0E5A43, #F2A53A and layouts; line icons and accessible controls.
- Keep device, demo and server workspaces distinct; no fake production data or verification.
- Shared interfaces are in shared/types.ts; all money is finite nonnegative taka, arithmetic rounds through integer poisha.
- Core data persists; sale inventory and idempotency changes are atomic; server enforces ownership.
- No credentials in client bundles or source control.

### Task 1: Persistent domain and authenticated backend

**Files:** shared/domain.ts, shared/domain.test.ts, server/**, server tests, docs/API.md, docs/SERVER.md.
**Consumes:** shared/types.ts. **Produces:** createWorkspace(shop: Partial<Shop>): Workspace; applyAction(state: Workspace, action: Action, now?: string): Workspace; dashboard(state: Workspace, now?: Date): Dashboard; creditScore(state: Workspace, now?: Date): Score. Functions must export these exact names.

- [ ] Write failing domain tests for stock validation, sale atomicity, duplicate requests, negative input, deletion history, payment claim deduplication and score data sufficiency; run to prove expected failure.
- [ ] Implement immutable transactional actions; identifiers use crypto.randomUUID; update state.version each mutation; cap activity history. Reject invalid money, quantities, malformed names and unexpected action fields. Shop changes use a strict whitelist.
- [ ] Implement Fastify API with Zod validation, bcrypt auth, hashed opaque revocable sessions, ownership, cookie CSRF/origin checks, rate limiting and persistent SQLite migrations. Routes and payloads are specified in task-1-brief.md.
- [ ] Implement server-key-only optional AI adapters and consent-restricted bank views with real bank offer creation. Never fake external integrations.
- [ ] Run real HTTP integration tests including unauthorized reads, cross-account access, idempotency, consent and session revocation. Document endpoint setup, backups and limitations.

### Task 2: Responsive application and persistent client

**Files:** src/**, index.html, vite.config.ts, tests/ui.spec.ts.
**Consumes:** shared/types.ts and Task 1 domain exports. **Produces:** bundled web app in dist.

- [ ] Add client persistence with separate namespaces; use domain transaction logic locally and API actions in server mode. Surface errors and offline read-only cache explicitly.
- [ ] Implement onboarding, authentic registration/login, inventory editing/search/filter/delete, multi-item sales, payment claim/review, score/consent, advice, camera capture/review, settings/export, notifications/activity.
- [ ] Build responsive merchant dashboard, public customer order view, and bank consent/offer portal. Preserve the references with GreenBiz branding, true data and clear empty states.
- [ ] Verify browser journeys for inventory persistence, sale stock changes, invalid values, demo separation, mobile navigation and desktop layout.

### Task 3: Android packaging and release verification

**Files:** android/**, capacitor.config.ts, README.md, .env.example, .github/workflows/ci.yml, docs/RELEASE.md.

- [ ] Generate Capacitor Android project; add camera permissions only when used, Keystore-backed token plugin and back navigation. Permit development cleartext only for loopback; release requires HTTPS.
- [ ] Build debug/internal APK with installed Android 35 tools. Keep signing keys out of source. Include release AAB configuration requiring owner's signing values.
- [ ] Run type checking, lint, domain/API tests, browser journeys, dependency audit and APK packaging; inspect app visually at phone/desktop widths; report exact untested device/integration limits.
- [ ] Create source archive and APK with checksum; write a release checklist, deployment instructions and a persistent progress ledger.
